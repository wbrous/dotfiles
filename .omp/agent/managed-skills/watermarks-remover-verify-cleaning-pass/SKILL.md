# Verifying a watermarks-remover cleaning pass

Scripts live in `~/.local/share/watermarks-remover/service/scripts/` (`clean_file.py`, `audit_dir.py`). `clean_file.py` has no `--dry-run`; to re-test a failure, copy the `.bak` to /tmp and run `clean_file.py <copy> --in-place --json` (output lists `actions` and `post_findings`).

## Steps
1. `find . -type f` the tree. Note `.bak` files with no entry in the "cleaned" list (the cleaner may have cleaned them anyway) and any README stating what must survive.
2. Text/markup: `cat -v` both versions; enumerate remaining `Cf/Zs/Co/Cc` chars with `unicodedata` per file (bak vs new).
3. PNG: parse chunks (tEXt/iTXt/zTXt/eXIf) and compare IDAT CRC to confirm pixels are unchanged. Check non-AI chunks (e.g. Title) survived.
4. docx/epub/odt: use `zipfile`, diff each member (split `><` into lines). Check `testzip()`, member order, and that `mimetype` is first and stored (compress_type 0) for epub/odt.
5. Run `audit_dir.py <dir>`. **The audit also scans `.bak` files**, so "residual actionable" counts include them. Separate real residuals from `.bak` noise; the true count is only meaningful after the `.bak` files are gone.
6. Check controls (false-positive files) by inspection; if no pristine `.orig` copy exists, byte-compare is impossible, so say so.
7. Delete `.bak` only for files verified clean. Keep `.bak` for any file with residual findings or lost data.

## Known behaviors seen (may change)
- ODT path doesn't blank `dc:description` ("Generated by Claude" survives) while DOCX/EPUB blank it, so a failed run on `.odt` was plausible.
- Bidi marks LRM/RLM/LRI/PDI are intentionally preserved (`_PRESERVABLE_BIDI_CPS`) yet audit still flags them "probable".
- `exotic_spaces.txt` is only "informational" and is left untouched.
- PNG cleaning dropped the benign `Title` chunk (README says it should survive).
- docx `Application` in app.xml gets blanked; DOCX/EPUB fields are emptied, not removed.
- Visible prose like "Generated by Claude" in body text is left alone.
