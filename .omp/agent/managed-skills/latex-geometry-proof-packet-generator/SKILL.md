## Workflow
1. Identify the exact vocabulary scope the student is restricted to (e.g. "Postulates 1-10" vs a longer list that includes 11-17). Cross-check any postulate/theorem numbering against the source photos/notes literally — do NOT assume later postulates (SSS/ASA/SAS/CPCTC/parallel-line postulates) are fair game just because they appear on the same reference page; the user may explicitly cap the range.
2. Design diagrams first as reusable TikZ snippets (rays from a point, X-crossing lines — draw at a SKEWED angle like 20°/110°/200°/-70° so right-angle-ness is never visually implied unless perpendicularity is actually given, collinear point rows via `\foreach \x/\lab in {...}`, triangles with cevians).
3. For "given fact -> blank conclusion/reason" drills: write ONLY the diagram + a numbered list of `Given: ...` statements with underline blanks for Conclusion and Reason. Do NOT compute/print the conclusion yourself — that's the exercise.
4. For fixed-step-count proofs (e.g. "must be exactly 15 steps, no stacking"): hand-derive the full statement/reason chain yourself on scratch first to confirm the step count is real and non-redundant (no unused branches, no two facts crammed into one statement, no leaps). A reliable padding technique: mirror the same short theorem-chain twice on two independent sub-figures, then join the two branches with one Transitive/Substitution step at the end — this reliably stretches a 5-7 step base proof to exactly 15 without artificial filler. Only print the diagram + Given/Prove + a BLANK statement/reason table in the PDF (don't print your worked solution unless asked).
5. Define the blank N-row table ONCE as a LaTeX macro (e.g. `\newcommand{\blanktable}{...}`) so you only type the repetitive rows a single time and just invoke the macro per proof.

## Gotchas
- **longtable inside a `\newcommand` macro invoked multiple times breaks** ("Extra alignment tab", "Misplaced \noalign", then "Undefined control sequence" on later calls) — use plain `tabular` wrapped in `\begin{center}...\end{center}` instead; it's safe to reuse across many invocations and still avoids page-overflow if you keep row height modest (~0.7cm) and put each proof's table on its own page via `\newpage`.
- **`\par` alone does not reliably force each numbered item onto its own line** when followed immediately by more macro-generated content — use explicit `\\` line breaks inside the item macro instead of `\par` for guaranteed line separation.
- **`\subsection{N}` inside a numbered `titlesec`-customized section produces ugly compound numbering** like "Proof 2.1" (section.subsection). Use `\subsection*{Proof N}` (starred, manual number in the text) instead of relying on the LaTeX counter when you want clean sequential labels across many blocks.
- **Watch for accidental double `\newpage`** at section transitions (one before `\section{...}`, another right after its intro paragraph) — this silently inserts a fully blank page. Only put one `\newpage` at each transition point.
- **`edit` tool CUT+PUT reordering risk**: cutting a large block and pasting it by line number is fragile once earlier edits shift line numbers — after any multi-hundred-line CUT/PUT, always re-`read` the file to confirm the paste landed in the intended location (e.g. inside `\begin{document}`, after macro definitions) before continuing to build on top of it. For large restructures it's often faster/safer to just rewrite the whole file fresh via `write` than to chain several CUT/PUT edits.
- Always compile with `pdflatex -interaction=nonstopmode` and grep the output for `error|undefined|misplaced|! ` rather than eyeballing the full log; then rasterize a few representative pages with `pdftoppm -png -r 100 -f N -l N` and `read` the PNG to visually confirm diagrams/tables render correctly (the `read` tool's text-extraction view of a PDF is not sufficient to judge TikZ diagram layout — you must render to an image).
